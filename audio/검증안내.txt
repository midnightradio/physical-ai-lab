라이브러리 기반 실습 예제 확인 범위
=================================

사용 버전: Arduino-ESP32 3.3.12, 보드 패키지에 포함된 ESP_I2S / SD / SD_MMC / FS

컴파일 및 링크 확인
-------------------
2026-11-19 내장 슬롯 버전: 변경된 WROOM SD/USB 예제를 직접 USB CDC와
USB-UART 설정에서 다시 컴파일하고 링크했습니다. XIAO 예제는 변경하지 않았습니다.
- XIAO + SD 저장 예제, 직접 USB CDC
- XIAO + 브라우저 수집기 예제, 직접 USB CDC
- WROOM + INMP441 + 브라우저 수집기, 직접 USB CDC
- WROOM + INMP441 + 브라우저 수집기, USB-UART
- WROOM + INMP441 + 보드 내장 microSD (SD_MMC 1비트), 직접 USB CDC
- WROOM + INMP441 + 보드 내장 microSD (SD_MMC 1비트), USB-UART

소프트웨어 동작 확인
-------------------
설치된 ESP_I2S의 recordWAV(), readBytes(), 32→16비트 변환 함수 본문을
시험용 마이크·통신·메모리 인터페이스에 연결해 실행했습니다.

- PDM / INMP441 경로의 1·2·3·5·10초 WAV 생성
- 16000Hz / 16비트 / 모노 / 녹음 길이 / PCM 소리 값 확인
- 부분 USB 전송, PSRAM 미활성, 마이크 초기화 실패, 읽기 실패,
  메모리 부족 등의 경로를 포함한 USB 예제 26개 시험
- PDM의 읽기 대기 시간을 늘리지 않으면 긴 녹음이 실패하는 조건 확인
- SD 예제가 recording_1.wav, recording_2.wav 두 파일을 만드는 동작
- WROOM + INMP441 SD 예제의 3초·10초 WAV 저장, SD_MMC 내부 핀(CLK39/CMD38/D0 40),
  1비트 모드·자동 포맷 안 함·20MHz 설정,
  기존 파일 보존과 다음 번호 저장, 초기화·녹음·파일 기록 실패를 포함한 14개 시험
- Chrome에서 수집기 연결·라벨 버튼·직접 입력·파형·저장 흐름 확인
- 공식 recordWAV()로 생성한 모의 10초 WAV의 브라우저 수신과 ZIP 저장
- ZIP 압축 검증과 저장된 WAV를 별도 도구로 재확인

추가 확인
---------
WROOM의 audio_capture_inmp441_usb / audio_capture_inmp441_sd 예제는 마이크 핀을 GPIO1·2·42로 통일했습니다.
CAM 카메라의 GPIO4·5·6 및 SD GPIO38·39·40과 겹치지 않는지 대조했습니다.
내장 SD 핀은 같은 보드 계열의 제조사 문서와 공식 SD_MMC API를 참고했습니다.
사진만으로 실제 PCB의 전기적 연속성이나 카드 동작을 측정한 것은 아닙니다.

실물 확인이 필요한 부분
-----------------------
실제 마이크 음질, 실제 보드의 핀 연결·PSRAM, 물리적인 USB 전송,
실제 microSD 카드의 파일 기록·재생 및 Edge Impulse 업로드는 실물 검증하지
않았습니다. 위 소프트웨어 시험이 실제 보드에서의 검증 완료를 뜻하지는 않습니다.
